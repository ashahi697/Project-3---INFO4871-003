# Project-3---INFO4871-003

For the final project in this course, you will demonstrate the extent to which you have achieved the course learning objectives, which are as follows:

Describe the ways in which information flows through web application stacks.
Design web applications for diverse users and justify trade-offs made among interfaces and architectures.
Build web applications using modern web technologies, following industry best practices.
Critique web applications on dimensions such as their usability and accessibility.
To do this, you will design and develop a full-stack web application, meaning that your application will need to have both a front-end layer (which we've spent the most time on in this course) and a back-end layer (which we turned our attention to starting in Week 9). An essential part of the design of your project will be scoping it well. What this means is that you will need to pick a project that is substantial yet not so complex that you won't be able to complete it. Scoping a project well is tricky, so you should start thinking about ideas for your final project earlier rather than later. Note that I will ask you individually about your final project ideas in class around the end of October: that way, you will get a chance to (1) see early in the process whether your ideas will lead to a sufficiently complex project, and (2) receive help in scoping your project to an appropriate level of difficulty.

As was the case with the other projects, you will need to complete a writeup for your final project, which will take place during the week of final exams. Our assigned exam block is Wednesday, December 9th, from 1:30pm to 4:00pm, in our usual classroom. Remember that you MUST complete the writeup for the project in order to get credit for your project. Note that there are two additional components to this project besides the writeup: you will present your final project to the class, and you will provide feedback on your peers' final projects. Be aware that presenting your web application and reviewing your peers' final projects (both during the workshopping week before the break and the presentation week after the break) are NOT optional: if you skip them, then your grade on Project 3 will be reduced.

The various components of this project are detailed below.

Peer Review. The week before the break, we will do peer review and workshopping of final projects during class. Note that it is not expected that your project will be finished by this point, but you will need to have enough of a work-in-progress to show to your peers and get feedback on. I will provide you with some questions to help guide your feedback as part of the review process.

Project Presentation. The last week of class is reserved for final project presentations. All final project presentations will occur during this week. The goal of your presentation is to demo your web application, including an explanation of what it is, why you built it, and how you approached building it. You do not need to make slides for your presentation, but you may choose to do so if you wish. Note that you must show up for all of the days of the final project presentations and pay attention to your peers' presentations.

Project Submission. Your submission should be an archive file (such as a ZIP file) containing all of the files needed for your web application as well as a text file (e.g., a PDF) that contains instructions for how to run your project. Do not include the source code of any third-party libraries (e.g., React or FastAPI) in your submission; if I need to install libraries in order to run your project, then this should be detailed in the instructions. After you submit your project, I would highly recommend downloading it and double-checking that your submission contains all of your application source code (in a readable, non-minified format) and the aforementioned text file.

Project Writeup. The project writeup format will be the same as before: I will give you a sheet of paper with prompts on it, and you will need to respond to the prompts in a blue book that you bring to the writeup. Like for the other projects, the purpose of the writeup is to demonstrate that you understand the project that you submitted and can clearly and correctly discuss aspects of it.

One final note: as was the case with the other projects, your project grade is not directly based on the code that you submit. Instead, it will be based on (1) the extent to which you made a reasonable attempt to complete the project according to the provided specifications, and (2) your project writeup. Note that because the project is much more open-ended compared to the previous two projects, the specifications are not details such as whether your project has certain pages or functionality. Instead, the specifications are that your project needs to be full-stack and sufficiently complex and that you need to engage in peer review and the project presentations.
